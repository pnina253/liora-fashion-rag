# Liora Fashion — בוט RAG למידע על חנות אופנה דמיונית

פרויקט לימודי ב־Python שמאפשר לשאול שאלות בעברית על מסמכי החנות ולקבל תשובה ממודל שפה המבוססת על קטעים שאוחזרו. אין גישה למלאי או להזמנות אמיתיות.

## טכנולוגיות והחלטות

- **LlamaIndex** לטעינה, חלוקה למקטעים, אינדוקס ואחזור.
- **ChromaDB** כמאגר וקטורי מקומי עם מדד cosine, הנשמר בדיסק.
- **Chunking** לפי כותרות Markdown, ובסעיפים ארוכים חלוקה עד 512 טוקנים עם חפיפה של 50.
- **Embeddings**: `text-embedding-3-small`; **מודל תשובה**: `gpt-4o-mini`, טמפרטורה 0.
- **Top-K**: חמישה מקטעים לתשובה.
- **חיפוש**: Hybrid — חיפוש וקטורי בשילוב BM25 מותאם לעברית; שילוב דירוגים באמצעות RRF ושימור מועמדים מובילים משני המנועים.
- **הרחבת שאילתה**: לא נדרשת בהרצה הנוכחית; ניתן לשפר בעתיד, אך אינה תנאי להפעלת המערכת.
- **ממשק**: Streamlit.

## התקנה והרצה

1. התקיני Python 3.12 וצרי סביבה וירטואלית: `py -3.12 -m venv .venv`.
2. הפעילי אותה והתקיני תלויות: `.venv\\Scripts\\python.exe -m pip install -r requirements.txt`.
3. צרי `.env` לפי `.env.example`, והגדירי `OPENAI_API_KEY` פרטי. **אין להעלות את `.env` להגשה**.
4. בהרצה הראשונה בלבד, אם `chroma_db` אינו קיים, הריצי `.venv\\Scripts\\python.exe ingest.py`. הפעולה יוצרת embeddings בתשלום, ומוחקת ובונה מחדש אוסף קיים — לא להריץ אם כבר יש מאגר תקין.
5. הפעילי את הממשק: `.venv\\Scripts\\python.exe -m streamlit run app.py`.
6. לבדיקת האחזור בלבד: `.venv\\Scripts\\python.exe retrieve_cli.py`.

## בסיס הידע והמקורות

שישה מסמכי Markdown בתיקיית `knowledge_base`: מוצרים, משלוחים, החזרות, הזמנות ותשלומים, מידות ושאלות נפוצות. כל תשובה בממשק מציגה גם את סעיפי המקור שאוחזרו. הקובץ `evaluation_questions.csv` משמש לבדיקות בלבד ואינו נטען לבסיס הידע.

## שלוש בעיות אמיתיות שנתגלו במהלך הפיתוח ואיך שופרו

1. **חיפוש סמנטי פספס התאמות מדויקות.** למשל, בשאלה על משלוחים לקנדה החיפוש הווקטורי לא מצא את סעיף `SH-01` בחמש התוצאות הראשונות. הוספנו BM25 מותאם לעברית ושילבנו אותו עם החיפוש הווקטורי. בגרסה המשופרת הסעיף הגיע למקום הראשון.
2. **שילוב RRF רגיל דחק מידע רלוונטי.** בשאלה על שמלת נועה סעיף המוצר `PR-DR-102` דורג שלישי ב־BM25 אך לא הגיע ל־Top-5 המשולב. בשאלה על הזמנה אישית `OP-06` דורג שלישי ב־Vector אך נעלם מה־Top-5. שיפרנו את בחירת התוצאות כך שתגן גם על מועמדים מובילים משני המנועים; שני הסעיפים הופיעו שוב ב־Top-5.
3. **שאלות הדורשות כמה מסמכים לא תמיד קיבלו את כל המקורות.** בדקנו 15 שאלות מול סעיפים צפויים, והשווינו Vector ו־Hybrid. המדד All-required@5 עלה מ־71.4% ב־Vector ל־92.9% ב־Hybrid המעודכן; בשאלה אחת (T10) עדיין חסר מקור נדרש.

## הערכה ומגבלות

בדוח `reports/retrieval_evaluation.md` יש 15 שאלות, מהן 14 בעלות מקור צפוי ושאלה אחת ללא תשובה. בגרסת Hybrid האחרונה: Hit@1 = 71.4%, Hit@5 = 100%, All-required@5 = 92.9%, MRR@5 = 0.824. אלה **מדדי אחזור**, ולא הוכחה לנכונות כל התשובות. מומלץ להדגים בממשק לפחות חמש שאלות, כולל שאלה שאין לה תשובה, ולוודא שהמודל אינו ממציא תשובה. התוכן דמיוני ואינו משקף מלאי או הזמנות בזמן אמת.
